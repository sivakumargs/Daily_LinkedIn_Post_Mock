𝗣𝗲𝗿𝗺𝗶𝘀𝘀𝗶𝗼𝗻𝘀.

In Linux, not every user should be allowed to read, modify, or execute every file.

This is where permissions become important.

🔎 𝗧𝗵𝗲 𝗯𝗮𝘀𝗶𝗰 𝗺𝗲𝗻𝘁𝗮𝗹 𝗺𝗼𝗱𝗲𝗹

Think about Linux permissions using three questions:

𝗪𝗛𝗢 can access the resource?

𝗪𝗛𝗔𝗧 can they do?

𝗪𝗛𝗘𝗥𝗘 does the permission apply?

Linux permissions are mainly divided into:

👤 Owner

👥 Group

🌍 Others

And each can have different permissions.

🔐 𝗧𝗵𝗲 𝘁𝗵𝗿𝗲𝗲 𝗯𝗮𝘀𝗶𝗰 𝗽𝗲𝗿𝗺𝗶𝘀𝘀𝗶𝗼𝗻𝘀

𝗿 = Read

Allows a user to read the contents of a file.

𝗪 = Write

Allows a user to modify the file.

𝗫 = Execute

Allows a user to execute a file or access a directory in the appropriate way.

A simple way to remember them:

𝗿 = 𝗥𝗲𝗮𝗱

𝘄 = 𝗪𝗿𝗶𝘁𝗲

𝘅 = 𝗘𝘅𝗲𝗰𝘂𝘁𝗲

💻 𝗖𝗵𝗲𝗰𝗸𝗶𝗻𝗴 𝗟𝗶𝗻𝘂𝘅 𝗽𝗲𝗿𝗺𝗶𝘀𝘀𝗶𝗼𝗻𝘀

The command I used is:

ls -l

For example:

-rwxr-x---

This permission string can be understood as:

Owner → rwx

Group → r-x

Others → ---

So permissions answer an important security question:

𝗪𝗵𝗼 𝗰𝗮𝗻 𝗱𝗼 𝘄𝗵𝗮𝘁?

🧮 𝗣𝗲𝗿𝗺𝗶𝘀𝘀𝗶𝗼𝗻 𝗻𝘂𝗺𝗯𝗲𝗿𝘀

Linux also represents permissions using numbers.

𝗿 = 4

𝘄 = 2

𝘅 = 1

Therefore:

𝗿𝘄𝘅 = 4 + 2 + 1 = 7

𝗿𝘄- = 4 + 2 = 6

𝗿-𝘅 = 4 + 1 = 5

𝗿-- = 4

--- = 0

For example:

750

means:

Owner → 7 → rwx

Group → 5 → r-x

Others → 0 → ---

🔧 𝗖𝗵𝗮𝗻𝗴𝗶𝗻𝗴 𝗽𝗲𝗿𝗺𝗶𝘀𝘀𝗶𝗼𝗻𝘀

The command I practiced is:

chmod 750 script.sh

This changes the permissions of the file.

I also practiced:

chmod 640 notes.txt

chmod u+x script.sh

The important thing is not just memorizing chmod.

The important thing is understanding what permission you are giving and to whom.

🔎 𝗦𝗼𝗺𝗲 𝗵𝗲𝗹𝗽𝗳𝘂𝗹 𝗰𝗼𝗺𝗺𝗮𝗻𝗱𝘀

ls -l

View file permissions.

chmod

Change file permissions.

stat notes.txt

View detailed file information and permissions.

🛡️ 𝗪𝗵𝘆 𝗱𝗼𝗲𝘀 𝘁𝗵𝗶𝘀 𝗺𝗮𝘁𝘁𝗲𝗿 𝗳𝗼𝗿 𝗗𝗲𝘃𝗦𝗲𝗰𝗢𝗽𝘀?

Security is not only about scanning code or containers.

The operating system itself must also be secured.

Incorrect permissions can allow unauthorized users or processes to access or modify resources.

In DevSecOps, understanding permissions helps when working with:

🔹 Servers

🔹 Containers

🔹 Application files

🔹 Configuration files

🔹 SSH keys

🔹 Deployment scripts

🔹 Logs

🔹 Secrets

🧠 𝗤𝘂𝗶𝗰𝗸 𝗺𝗲𝗺𝗼𝗿𝘆 𝘁𝗿𝗶𝗰𝗸

📌 𝗞𝗲𝘆 𝘁𝗮𝗸𝗲𝗮𝘄𝗮𝘆

Linux permissions determine who can read, change, or execute a resource.

As a DevSecOps engineer, I should never blindly give maximum permissions.

The goal is to give users and processes only the access they actually need.
