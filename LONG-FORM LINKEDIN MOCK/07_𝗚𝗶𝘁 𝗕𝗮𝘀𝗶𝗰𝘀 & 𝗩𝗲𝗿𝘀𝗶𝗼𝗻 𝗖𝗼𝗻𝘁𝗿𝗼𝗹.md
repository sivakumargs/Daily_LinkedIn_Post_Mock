𝗧𝗼𝗱𝗮𝘆 𝗜 𝗹𝗲𝗮𝗿𝗻𝗲𝗱 𝗚𝗶𝘁 𝗯𝗮𝘀𝗶𝗰𝘀.

Yesterday, I learned how SSH provides secure remote access to Linux systems. Today, I started learning how Git helps developers track changes and manage code.

🔎 𝗧𝗵𝗲 𝗯𝗮𝘀𝗶𝗰 𝗺𝗲𝗻𝘁𝗮𝗹 𝗺𝗼𝗱𝗲𝗹

Git is a distributed version control system.

It helps me track changes to files, understand what changed, and return to an earlier version when needed.

𝗪𝗼𝗿𝗸𝗶𝗻𝗴 𝗱𝗶𝗿𝗲𝗰𝘁𝗼𝗿𝘆 → 𝗦𝘁𝗮𝗴𝗶𝗻𝗴 → 𝗖𝗼𝗺𝗺𝗶𝘁

The working directory contains my current changes.

The staging area contains the changes I want to include.

A commit records those staged changes in Git history.

💻 𝗨𝘀𝗲𝗳𝘂𝗹 𝗚𝗶𝘁 𝗰𝗼𝗺𝗺𝗮𝗻𝗱𝘀

git init

Creates a new Git repository.

git status

Shows the current state of the working directory.

git add <file>

Stages a file for the next commit.

git commit -m "message"

Creates a commit with a message.

git log

Shows the commit history.

git diff

Shows changes that have not been committed.

🛡️ 𝗪𝗵𝘆 𝗱𝗼𝗲𝘀 𝘁𝗵𝗶𝘀 𝗺𝗮𝘁𝘁𝗲𝗿 𝗳𝗼𝗿 𝗗𝗲𝘃𝗦𝗲𝗰𝗢𝗽𝘀?

Git is a foundation for modern DevOps and DevSecOps workflows.

It helps teams:

🔹 Track code changes
🔹 Review changes
🔹 Collaborate safely
🔹 Identify what changed
🔹 Roll back when necessary
🔹 Connect source code with CI/CD pipelines

Security also benefits from understanding exactly what changed and when.

🧪 𝗧𝗼𝗱𝗮𝘆'𝘀 𝗽𝗿𝗮𝗰𝘁𝗶𝗰𝗲

I created a small practice repository:

cd devsecops-git-practice

Then I practiced:

git commit -m "Initial commit"

The goal was not just to memorize Git commands.

The goal was to understand how Git tracks changes.
