Yesterday, I learned about Linux file permissions. Today, I learned how Linux manages running programs and background services.

🔎 𝗧𝗵𝗲 𝗯𝗮𝘀𝗶𝗰 𝗺𝗲𝗻𝘁𝗮𝗹 𝗺𝗼𝗱𝗲𝗹

A process is a running instance of a program.

A service is a background application managed by the system.

Every running process has a unique number called a PID.

💻 𝗣𝗿𝗼𝗰𝗲𝘀𝘀𝗲𝘀

ps aux

Shows running processes.

top

Shows processes and resource usage in real time.

pgrep nginx

Finds the PID of a process.

kill <PID>

Sends a signal to a process.

⚙️ 𝗦𝗲𝗿𝘃𝗶𝗰𝗲𝘀

Services are background applications that can be managed by Linux.

systemctl status nginx

Checks the service status.

systemctl start nginx

Starts the service.

systemctl stop nginx

Stops the service.

systemctl enable nginx

Configures the service to start automatically during boot.

🛡️ 𝗪𝗵𝘆 𝗱𝗼𝗲𝘀 𝘁𝗵𝗶𝘀 𝗺𝗮𝘁𝘁𝗲𝗿 𝗳𝗼𝗿 𝗗𝗲𝘃𝗦𝗲𝗰𝗢𝗽𝘀?

When an application is not working, I need to understand what is happening underneath.

I need to ask:

🔹 Is the process running?
🔹 Is the service running?
🔹 Is it consuming too much CPU or memory?
🔹 Did the service fail?
🔹 Is the service configured to start automatically?

Understanding processes and services helps with:

🔹 Troubleshooting applications
🔹 Monitoring systems
🔹 Managing servers
🔹 Supporting deployments
🔹 Automation

🧪 𝗧𝗼𝗱𝗮𝘆'𝘀 𝗽𝗿𝗮𝗰𝘁𝗶𝗰𝗲

I practiced:

ps aux

top

pgrep <process-name>

systemctl status <service>

systemctl enable <service>

The goal was not just to memorize commands.

The goal was to understand the difference between a running process and a managed service.
