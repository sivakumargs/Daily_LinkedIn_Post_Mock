🔎 𝗧𝗵𝗲 𝗯𝗮𝘀𝗶𝗰 𝗺𝗲𝗻𝘁𝗮𝗹 𝗺𝗼𝗱𝗲𝗹

𝗚𝗶𝘁 = Version control

𝗚𝗶𝘁𝗛𝘂𝗯 = Online platform for hosting Git repositories and collaborating.

𝗥𝗲𝗽𝗼𝘀𝗶𝘁𝗼𝗿𝘆 = A project and its tracked history.

𝗕𝗿𝗮𝗻𝗰𝗵 = An independent line of development.

Branches allow me to work on new features without immediately changing the main branch.

💻 𝗨𝘀𝗲𝗳𝘂𝗹 𝗚𝗶𝘁 𝗰𝗼𝗺𝗺𝗮𝗻𝗱𝘀

git clone <repository-url>

Downloads an existing repository to my local machine.

git branch

Lists local branches.

git switch -c feature/update-readme

Creates and switches to a new branch.

git switch main

Switches back to the main branch.

git merge feature/update-readme

Merges the feature branch into the current branch.

git remote -v

Shows configured remote repositories.

git push -u origin main

Pushes the local main branch to the remote repository and sets its upstream.

🛡️ 𝗪𝗵𝘆 𝗱𝗼𝗲𝘀 𝘁𝗵𝗶𝘀 𝗺𝗮𝘁𝘁𝗲𝗿 𝗳𝗼𝗿 𝗗𝗲𝘃𝗦𝗲𝗰𝗢𝗽𝘀?

DevSecOps involves more than writing commands and scripts.

I need to manage infrastructure code, configuration files, automation scripts, and application source code.

Git and GitHub help teams:

🔹 Collaborate on projects
🔹 Review code changes
🔹 Separate feature development from the main branch
🔹 Track changes and investigate issues
🔹 Integrate code with CI/CD pipelines
🔹 Review security changes before merging

A branch gives me a safer place to experiment, while code reviews help identify problems before changes reach the main branch.

🧪 𝗧𝗼𝗱𝗮𝘆'𝘀 𝗽𝗿𝗮𝗰𝘁𝗶𝗰𝗲

I created a local Git repository and practiced working with branches.

git init devsecops-practice
cd devsecops-practice

git switch -c feature/update-readme

echo "# My DevSecOps Journey" > README.md

git add README.md
git commit -m "Add project README"

git switch main
git merge feature/update-readme

Then I checked my repository history:

git log --oneline
git branch

To publish my project, I would create a GitHub repository, configure the remote, and push my branch.

The goal was not just to memorize commands.

The goal was to understand how developers collaborate without losing track of changes.
