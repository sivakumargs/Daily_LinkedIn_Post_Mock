Yesterday, I learned about SSH and secure remote access. Today, I started learning how Git tracks changes and manages code history.

🔎 𝗧𝗵𝗲 𝗯𝗮𝘀𝗶𝗰 𝗺𝗲𝗻𝘁𝗮𝗹 𝗺𝗼𝗱𝗲𝗹

Git is a distributed version control system.

𝗪𝗼𝗿𝗸𝗶𝗻𝗴 𝗱𝗶𝗿𝗲𝗰𝘁𝗼𝗿𝘆 → 𝗦𝘁𝗮𝗴𝗶𝗻𝗴 → 𝗖𝗼𝗺𝗺𝗶𝘁

I make changes, stage the changes I want to save, and commit them into Git history.

💻 𝗨𝘀𝗲𝗳𝘂𝗹 𝗰𝗼𝗺𝗺𝗮𝗻𝗱𝘀

git init

→ Creates a Git repository.

git status

→ Shows the current state.

git add <file>

→ Stages a file.

git commit -m "message"

→ Records the staged changes.

git log

→ Shows commit history.

git diff

→ Shows changes that have not been committed.

🛡️ 𝗪𝗵𝘆 𝗱𝗼𝗲𝘀 𝘁𝗵𝗶𝘀 𝗺𝗮𝘁𝘁𝗲𝗿 𝗳𝗼𝗿 𝗗𝗲𝘃𝗦𝗲𝗰𝗢𝗽𝘀?

Git is a foundation for DevOps and DevSecOps workflows.

It helps teams track changes, review code, collaborate, understand what changed, and roll back when necessary.

It also connects directly with CI/CD workflows.

cd devsecops-git-practice

Then practice:

git status

git add README.md

git commit -m "Initial commit"

The goal is not just to memorize commands.

The goal is to understand how Git tracks changes.
