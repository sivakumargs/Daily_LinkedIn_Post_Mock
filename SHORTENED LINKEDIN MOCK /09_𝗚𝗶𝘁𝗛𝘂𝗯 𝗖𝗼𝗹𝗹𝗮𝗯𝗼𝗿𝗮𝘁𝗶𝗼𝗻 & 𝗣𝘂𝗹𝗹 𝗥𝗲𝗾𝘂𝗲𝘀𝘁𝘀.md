Yesterday, I learned about Git repositories and branches. Today, I learned how developers propose changes and collaborate through code reviews.

🔎 𝗧𝗵𝗲 𝗯𝗮𝘀𝗶𝗰 𝗺𝗲𝗻𝘁𝗮𝗹 𝗺𝗼𝗱𝗲𝗹

A Pull Request (PR) is a proposal to merge changes from one branch into another.

𝗕𝗿𝗮𝗻𝗰𝗵 → 𝗖𝗵𝗮𝗻𝗴𝗲𝘀 → 𝗣𝘂𝘀𝗵 → 𝗣𝗥 → 𝗥𝗲𝘃𝗶𝗲𝘄 → 𝗠𝗲𝗿𝗴𝗲

💻 𝗨𝘀𝗲𝗳𝘂𝗹 𝗰𝗼𝗺𝗺𝗮𝗻𝗱𝘀

git switch -c feature/update-readme

→ Creates a feature branch.

git status

→ Checks repository status.

git add README.md

→ Stages changes.

git commit -m "Update project README"

→ Records changes.

git push -u origin feature/update-readme

→ Pushes the branch to GitHub.

git diff main...feature/update-readme

→ Shows changes introduced by the feature branch.

After pushing, open GitHub and create a Pull Request into main.

🛡️ 𝗪𝗵𝘆 𝗱𝗼𝗲𝘀 𝘁𝗵𝗶𝘀 𝗺𝗮𝘁𝘁𝗲𝗿 𝗳𝗼𝗿 𝗗𝗲𝘃𝗦𝗲𝗰𝗢𝗽𝘀?

Pull Requests help teams review code, discuss improvements, identify bugs, and check security risks before merging.

Automated CI/CD checks can run tests, dependency checks, and security scans against proposed changes.

This helps catch problems earlier in the development process.

🧪 𝗧𝗼𝗱𝗮𝘆'𝘀 𝗽𝗿𝗮𝗰𝘁𝗶𝗰𝗲

Create a feature branch in a test repository, make a small change, commit it, and push it to GitHub.

Open a Pull Request and review the proposed changes before merging.
