Yesterday, I learned about Linux file permissions. Today, I learned how Linux manages running programs and background services.

🔎 𝗧𝗵𝗲 𝗯𝗮𝘀𝗶𝗰 𝗺𝗲𝗻𝘁𝗮𝗹 𝗺𝗼𝗱𝗲𝗹

𝗣𝗿𝗼𝗰𝗲𝘀𝘀 = A running instance of a program.

𝗦𝗲𝗿𝘃𝗶𝗰𝗲 = A background application managed by the system.

Every process has a unique PID — Process ID.

💻 𝗨𝘀𝗲𝗳𝘂𝗹 𝗰𝗼𝗺𝗺𝗮𝗻𝗱𝘀

ps aux

→ Shows running processes.

top

→ Shows processes and resource usage in real time.

pgrep nginx

→ Finds the PID of a process.

systemctl status nginx

→ Checks service status.

systemctl start nginx

→ Starts a service.

systemctl stop nginx

→ Stops a service.

systemctl enable nginx

→ Starts the service automatically during boot.

🛡️ 𝗪𝗵𝘆 𝗱𝗼𝗲𝘀 𝘁𝗵𝗶𝘀 𝗺𝗮𝘁𝘁𝗲𝗿 𝗳𝗼𝗿 𝗗𝗲𝘃𝗦𝗲𝗰𝗢𝗽𝘀?

When an application is not working, I need to understand what is happening underneath.

Is the process running?

Is the service running?

Is it consuming too much CPU or memory?

Did the service fail?

Understanding processes and services helps with troubleshooting, monitoring, deployments, and automation.

🧪 𝗧𝗼𝗱𝗮𝘆'𝘀 𝗽𝗿𝗮𝗰𝘁𝗶𝗰𝗲

ps aux

top

systemctl status <service>

systemctl start <service>

systemctl stop <service>

systemctl enable <service>

The goal is not just to memorize commands.

The goal is to understand the difference between a running process and a managed service.
