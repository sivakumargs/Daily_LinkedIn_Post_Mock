𝗧𝗼𝗱𝗮𝘆 𝗜 𝗹𝗲𝗮𝗿𝗻𝗲𝗱 𝗟𝗶𝗻𝘂𝘅 𝗳𝗶𝗹𝗲 𝗽𝗲𝗿𝗺𝗶𝘀𝘀𝗶𝗼𝗻𝘀.

Yesterday, I learned basic Linux commands. Today, I learned how Linux controls access to files and resources.

🔎 𝗧𝗵𝗲 𝗯𝗮𝘀𝗶𝗰 𝗺𝗲𝗻𝘁𝗮𝗹 𝗺𝗼𝗱𝗲𝗹

Linux permissions answer two questions:

𝗪𝗛𝗢 → Owner, Group, Others

𝗪𝗛𝗔𝗧 → Read, Write, Execute

🔐 𝗧𝗵𝗲 𝘁𝗵𝗿𝗲𝗲 𝗽𝗲𝗿𝗺𝗶𝘀𝘀𝗶𝗼𝗻𝘀

𝗿 = Read = 4

𝘄 = Write = 2

𝘅 = Execute = 1

For example:

𝗿𝘄𝘅 = 7

𝗿𝘄- = 6

𝗿-𝘅 = 5

--- = 0

So:

750

Owner → rwx

Group → r-x

Others → ---

💻 𝗖𝗵𝗲𝗰𝗸 𝗽𝗲𝗿𝗺𝗶𝘀𝘀𝗶𝗼𝗻𝘀

ls -l

Change permissions:

chmod 750 script.sh

chmod 640 notes.txt

chmod u+x script.sh

View detailed information:

stat notes.txt

🛡️ 𝗪𝗵𝘆 𝗱𝗼𝗲𝘀 𝘁𝗵𝗶𝘀 𝗺𝗮𝘁𝘁𝗲𝗿 𝗳𝗼𝗿 𝗗𝗲𝘃𝗦𝗲𝗰𝗢𝗽𝘀?

Incorrect permissions can allow unauthorized users or processes to access or modify resources.

This matters when working with:

🔹 Servers

🔹 Containers

🔹 Configuration files

🔹 SSH keys

🔹 Deployment scripts

🔹 Logs and secrets

🧪 𝗧𝗼𝗱𝗮𝘆'𝘀 𝗽𝗿𝗮𝗰𝘁𝗶𝗰𝗲

mkdir -p ~/devsecops-practice/day4

cd ~/devsecops-practice/day4

touch script.sh notes.txt

ls -l

chmod 750 script.sh

chmod 640 notes.txt

ls -l

The goal is not just to memorize chmod numbers.

It is to understand who has access and why.

🧠 𝗤𝘂𝗶𝗰𝗸 𝗺𝗲𝗺𝗼𝗿𝘆 𝘁𝗿𝗶𝗰𝗸

𝗪𝗛𝗢 → Owner + Group + Others

𝗪𝗛𝗔𝗧 → Read + Write + Execute

𝗿 = 4 | 𝘄 = 2 | 𝘅 = 1

📌 𝗞𝗲𝘆 𝘁𝗮𝗸𝗲𝗮𝘄𝗮𝘆

Do not blindly give maximum permissions.

Give users and processes only the access they actually need.
